Preserve IsoCity’s existing MIT notice as well. `idb` is included in in-product credits and the distributed notice text; research-only options are not presented as product dependencies. No upstream issue or contribution was claimed or submitted.

The `idb` source review covered `src/entry.ts`, `src/database-extras.ts`, transaction tests and README transaction lifetime. Writes report success after `tx.done`; snapshot preparation and hashing run before opening the transaction. Each atomic commit writes content and metadata together. Save queuing preserves order; immutable checkpoint IDs retain three recent states per world and twelve overall. Explicit optimistic revisions reject an outdated tab. Legacy localStorage migration hashes the exact validated content, commits it before removal, and leaves any later cross-tab localStorage value intact. Invalid recent checkpoints fall back within the same world.

The standalone server reuses PANGEA’s actual `.mjs` engine rather than reproducing its rules. SQLite transactions persist snapshot/revision/pause/rate/clock/backlog and rotating recovery checkpoints together. Opaque owner capabilities are hashed in storage; every world read and write requires authorization. Origins are explicitly allowed, request bodies are bounded, imported states are validated, and conflicting commands return409. The tick scheduler is independent of HTTP requests and keeps any work it cannot complete in a durable backlog. A failed step restores the last committed state before it can be served or retried.

Evidence: `tests/pangea/persistence.test.mjs` exercises real HTTP and SQLite; `tests/pangea/persistence-browser.py` exercises actual Chromium IndexedDB; `tests/pangea/server-browser.py` exercises the real app against an isolated server. Deployment and scope are described in [PERSISTENCE.md](../PERSISTENCE.md).
